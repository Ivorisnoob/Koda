# UI conventions

Reference detail moved out of `CLAUDE.md` so it loads only when needed. `CLAUDE.md` keeps the summary, the invariants and the silent-failure index; this file keeps the reasoning and the scars. Markers (`[verified]`, `[scar]`, `[judgement]`, `[drifts]`) mean what `CLAUDE.md` says they mean. If a change contradicts a sentence here, fix the sentence in the same commit.

- Music albums and playlists are both rendered by `PlaylistDetailScreen` in `LibraryScreen.kt`; the standalone `AlbumScreen.kt` has no callers. Their header exposes Play all and Shuffle through `CollectionPlaybackActions`, with secondary Save/Download actions in a wrapping group. The floating play menu appears after the header scrolls away or during search; manage mode retains its Done toolbar. Radio is also in the page overflow so it remains reachable at the top. Album order, filtered playback and duplicate-safe editing must survive any layout change.

- **Ask Google's image hosts for the size you are going to draw** (`data/ThumbnailUrls.kt`). InnerTube hands out avatars and covers at whatever size the surface it was built for needed - a search result's channel avatar comes back at `=s48`, a playlist cover at `w120-h120` - and Koda draws several of those at 140dp, which is 420 physical pixels on a 3x screen. That is the "why is this so blurry" report. `googleImageAtSize` rewrites the directive, splitting on the **last `=`** for the reason `Song.highResThumbnailUrl` does: the opaque token before the separator can itself contain `s<digits>` runs, and an unanchored replace turns the URL into a permanent 404. A larger request is a request, never a guarantee - Google serves the nearest size it has - so the result is always drawn *over* the original rather than instead of it, and `ui/components/AvatarImage.kt` is that layering plus `VideoThumbnail`'s loading machinery under an honest name. Not everything wants it: a 48dp quick-pick row asking for 1080 fetches a megabyte to fill a thumbnail and evicts the covers that needed it.
- **Every video frame big enough to notice goes through `ui/components/VideoThumbnail.kt`.** [scar] `VideoItem.highResThumbnailUrl` rewrites a feed's mq/hq/sd URL to `maxresdefault`, which YouTube only generates for sources uploaded at 720p or better - so it 404s for a large minority of videos, and a card that requested only that one drew an empty plate with nothing logged. The feed's own URL is drawn underneath and the high-res fades in on top, the layering `SongArtwork` already used for covers. Coil never retries a failed request either, so one dropped fetch left a card blank for as long as it stayed in the list; two delayed attempts cover a moment of no signal, and a genuine 404 exhausts them in about two seconds and settles on a broken-image state rather than a spinner that will never finish. The M3 `LoadingIndicator` is held off 180ms so a memory-cache hit never flashes one on a fling. It is also the one place that knows a `device:` id has no URL at all and must draw through `LocalVideoThumbnail`.
- **Material 3 Expressive first** (`LoadingIndicator` with shapes, `FloatingToolbar`, `MaterialShapes`, spring physics), standard M3 second. Do not hand-roll components or animation systems that M3 or `androidx.compose.animation` already provide.
- **Every snackbar goes through `ui/components/DismissibleSnackbarHost.kt`**, never `SnackbarHost` directly. Material's Compose snackbar has no dismissal gesture at all - the View one it replaced has swiped away for a decade - so an undo toast covered what was underneath for its full duration and the only way to be rid of it was to perform the action being offered. The shared host adds drag-to-dismiss down or sideways (up is rubber-banded: above it is content), a `dismiss` semantics action so the gesture is not the only route with a screen reader on, and a spring home for a drag that does not commit. It settles as `SnackbarResult.Dismissed`, the same result a timeout gives, so the twelve call sites' existing `if (result == ActionPerformed)` undo branches needed no change - **which also means a new caller must keep treating `Dismissed` as "the offer lapsed, the action stands"**, because a swipe now produces it deliberately rather than only by running out of time. It lives in `ui/components/` rather than beside one screen for the same reason `QueueReorder.kt` does: music, video, settings and both history screens all host one.
- Compiler-level opt-ins for `ExperimentalMaterial3ExpressiveApi` and `ExperimentalMaterial3Api` are global (`freeCompilerArgs`).
- Shared look: `Surface` cards with `RoundedCornerShape(16.dp)`, `surfaceContainer` colors, `ExpressivePullToRefresh`, staggered `AnimatedVisibility` entrances. Match neighbouring code.
- **Springs for anything touch-driven** (~120 uses [drifts]; `DampingRatioMediumBouncy` is the house default). Reserve `tween()` for crossfades and time-tracking progress.
- **The interface scale is a density override, and that is the only way it could have been.** `IvorMusicTheme` provides a `LocalDensity` whose `density` is multiplied by the user's `ui_scale` (`ScaledDensity` in `ui/theme/Theme.kt`), so all 3,671 `dp` literals across 99 files [drifts] resize at once and every proportion the design was drawn at survives. Retuning the literals would have been the same feature and a permanent tax on every layout written afterwards. Three consequences worth knowing: **`fontScale` is deliberately left alone** rather than divided back out, so `sp` rides along with the chrome and the user's system font setting still multiplies on top; **every `LocalDensity` read in the app is a consumer, never a provider** - the ~30 existing `dp.toPx()` call sites follow the scale for free, and a second provider below the theme would silently desync a subtree from the rest of the app; and **Glance widgets, the media notification and Android Auto do not inherit it**, correctly, since another process draws them and they should match its density.
- **A scale committed mid-drag fights the finger holding it.** `DisplaySizeSettingsPage` previews on every step and writes only on `onValueChangeFinished`, because applying each intermediate value rescales the page the slider is sitting on and moves the thumb away from the touch. The preview is a nested override of the same local, multiplied by `pending / committed` because the page is already drawn at the committed scale.
- Material icons extended is available (`Icons.Rounded.*`).
