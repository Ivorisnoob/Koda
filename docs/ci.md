# CI and release announcements (`.github/workflows/`)

Reference detail moved out of `CLAUDE.md` so it loads only when needed. `CLAUDE.md` keeps the summary, the invariants and the silent-failure index; this file keeps the reasoning and the scars. Markers (`[verified]`, `[scar]`, `[judgement]`, `[drifts]`) mean what `CLAUDE.md` says they mean. If a change contradicts a sentence here, fix the sentence in the same commit.

Three workflows, and **every one hangs off an `authorize` job that runs first**: `build.yml` (debug and release APKs, ABI splits, uploaded as artifacts), `codeql.yml` (`actions` and `java-kotlin`, manual build mode running `assembleDebug` because autobuild guesses wrong on Android projects), and `telegram-notify.yml` (star milestones and release announcements). Workflow-level `permissions: {}` is the default in all three; each job re-adds only what it needs.

**Judge APK size from the minified release, never the debug APK.** [verified August 2026] The 4.7 arm64 release was 14.01 MiB versus 11.20 MiB for 4.6; the actual artifact diff put the growth in DEX plus the production Cast, Glance/WorkManager and 25-language resources, not tests or debug tooling. The unminified debug APK was about 104 MiB because it contains full Compose tooling and extended icons, while `testImplementation`, `androidTestImplementation` and `debugImplementation` were absent from the release archive. `androidResources.localeFilters` must stay identical to `res/xml/locales_config.xml`: without it, transitive libraries advertised more than eighty language configurations that Koda does not support and inflated `resources.arsc`. Keep NewPipe's R8 rules narrow to its reflected time-ago patterns and protobuf fields; keeping the whole extractor pins unused services and methods. Rhino's broad keep is different and load-bearing because it executes YouTube JavaScript dynamically. Do not restore the obsolete yt-dlp/Python keep rules unless that dependency itself returns.

**The authorize gate is not a formality and its denials are not bugs to fix.** A run proceeds only when the actor has write access: a same-repo PR is authorized by construction, pushes and `workflow_dispatch` need the actor to be the owner or in `TRUSTED_ACTORS`, and a fork PR needs `author_association` of `OWNER`, `MEMBER` or `COLLABORATOR`. A fork PR from an outside contributor builds nothing, deliberately, because analysing it means running that fork's Gradle build on a runner. Those runs appear as `action_required` and even once approved the gate skips every build job and writes a "Build skipped" summary. Widening the `case` lists is the owner's call per contributor, not a cleanup.

**A red run with no logs is GitHub, not the code.** `The job was not acquired by Runner of type hosted even after multiple attempts`, with an empty `runner_name` and nothing from `gh run view --log-failed`, means no runner ever picked it up. Re-run rather than debug.

**`telegram-notify.yml` does not trigger on push.** It fires on `watch` (stars) and `release: published` only, so a change cannot be verified by pushing and the first live run of any edit is a real release. Test it by extracting the `run:` block and executing it with `curl` and `jq` stubbed, as the current one was checked against a real release payload.

**Those changelog bullets are read by the beta testers, on a phone, as their brief.** That is what the accumulated `Changelog:` sections become when the APK is delivered - not release-note filler but the list of things somebody is about to go and check. Write each bullet so it names what visibly changed and where, in the words of someone using the app rather than someone who read the diff, and keep it standing alone: several commits' bullets arrive in one message with no commit boundaries between them.

**The APK post is a separate, authorized PR-only path inside `build.yml`.** The release job still cannot run until `authorize` allows it, and fork PRs still cannot enter it because they receive no signing or bot secrets. After the signed universal APK reaches `@ivorisnoob_chat` (or its over-limit artifact link does), the same step sends the accumulated `Changelog:` sections from every commit after the head of the last successful same-branch PR workflow. The APK/link message is labelled **Latest beta**, pinned with `disable_notification=true`, then the formerly most-recent pin is removed only after the new pin succeeds; pin permissions are best-effort and must never turn a successful APK delivery into a failed build. It reads the changelog checkpoint from Actions history with `actions: read`; canceled and failed runs therefore do not advance it, so their entries roll into the next delivered APK without a writable state file. On the first delivery, an unavailable history response, or rewritten ancestry, it falls back to every commit on the current PR - a possible repeat is safer than a silent omission. The PR title is deliberately absent. Changelogs are plain text, chronological, and split below Telegram's UTF-16 message ceiling. [verified September 2026]

**Telegram's HTML mode is a small, strict parser that rejects the whole message on one malformed tag.** It understands `b/i/u/s/a/code/pre/blockquote/tg-spoiler` and nothing else, capped at 4096 UTF-16 units. Release notes are free-text Markdown, so `notes_to_html` escapes `&`, `<` and `>` first and only then adds tags we control, and **every conversion rule is line-local on purpose** - that is what makes trimming whole lines to fit the budget tag-balanced. The notes budget is whatever the header, asset list and footer leave over, not a constant. If Telegram rejects the markup anyway the message is resent as plain text, because a release with no announcement is worse than one announced unformatted.

**Free text reaches the script as data, never through `${{ }}` interpolation into the shell.** Release bodies and names arrive as environment variables, while APK changelog subjects and bullets are read from Git after checkout. `github.event.release.assets` arrives as `toJSON(...)` and can legitimately be empty, since a release is often published before its APKs finish uploading.

**`OWNER_URL` is the author-link convention and both files share it.** `author_html()` renders the repository owner's login as a link to `https://ivorisnoob.lol` and anyone else as plain text, matched case-insensitively against `github.repository_owner`. Keep the two copies in agreement and never link a non-owner to that site.
