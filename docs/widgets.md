# Home screen widgets (`widget/`)

Reference detail moved out of `CLAUDE.md` so it loads only when needed. `CLAUDE.md` keeps the summary, the invariants and the silent-failure index; this file keeps the reasoning and the scars. Markers (`[verified]`, `[scar]`, `[judgement]`, `[drifts]`) mean what `CLAUDE.md` says they mean. If a change contradicts a sentence here, fix the sentence in the same commit.

Pulse, Console, Deck, Lineup, Bloom and Orbit - all Glance, sharing one design kit (`WidgetKit.kt`, with `WidgetShapes.kt` and `WidgetTheme.kt`), one state layer (`PlayerWidgetCommon.kt`) and one publisher (`PlayerWidgetHost.kt`, `PlayerWidgets.publish`). Three rules hold them up and every one is a bug that shipped once.

**A `MediaController` may only be touched on its application thread, and Glance never gives you that thread.** `provideGlance` and every `ActionCallback.onAction` run on a background dispatcher while the controller binds to the main looper, so a direct `controller.play()` throws `IllegalStateException` - into a `catch (e: Exception)` that logs and moves on, which is why the symptom was "the buttons do nothing, sometimes". Everything that speaks to a session goes through `withController`, which wraps the block in `withContext(Dispatchers.Main)`.

**Widgets render from a stored snapshot, never a live session read.** `MusicService.onEvents` writes `player.toWidgetSnapshot()` into `PlayerWidgetStore` (through `PlayerWidgets.publish`) on its own player thread, inside the callback that reported the change, then pushes; a redraw is a preference read. The version that bound a controller per render was wrong constantly for three compounding reasons - the read happened at an arbitrary moment relative to the change that triggered it, six widgets raced for the same answer, and a bind that timed out blanked every widget to "Tap to listen". A controller is bound for exactly two things: issuing a command, and bootstrapping the store the first time. **`onEvents` rather than individual overrides is deliberate** - the scattered version pushed only on the *pause* edge of `onIsPlayingChanged` and had no push at all for shuffle or repeat.

**Play/pause masks locally; skips do not.** Media3 applies `play()`/`pause()` optimistically, so the state reads straight back through the same controller. Skips cannot, because `onPlayerCommandRequest` intercepts `COMMAND_SEEK_TO_NEXT`/`PREVIOUS` to route them through the crossfade engine and answers `RESULT_ERROR_NOT_SUPPORTED`, which suppresses the masking - a read taken immediately after a skip returns the *previous* track. Skips therefore settle before reading back. Relatedly the snapshot's `isPlaying` is `playWhenReady`, not `Player.isPlaying`: the widget shows intent, so the glyph flips on tap rather than after the first buffer.

**One widget draws with no card, and the empty state is why it is a special case.** `WidgetSurface` takes a nullable background; Bloom passes null so its cookie sits straight on the wallpaper, which is the only ground the scallop reads against. Its empty state still takes the card, because theme-coloured text on an unknown wallpaper is the one thing there that cannot supply its own contrast. The corner clip stays either way - it is the ripple's shape, not the card's - and below API 31 `cornerRadius` is a no-op, so on API 30 that ripple is a full rectangle over a transparent cell.

**Picker previews are literals by necessity and a palette by choice.** A launcher inflates `previewLayout` outside the app theme, so every colour in `res/drawable/widget_preview_*` and `res/layout/widget_preview_*` is fixed; the roles are documented at the top of `widget_preview_card.xml` and the family shares them. Two rules those files exist to keep: a glyph on the hero is `onPrimary` rather than white, because the hero is a light tone and white on it fails contrast; and nothing in a preview may use a platform-styled widget, because `?android:attr/progressBarStyleHorizontal` draws in the *device's* accent and made one element a different colour on every phone the picker was opened on.

Design constraints: **shape carries the hierarchy** (no ripples, no morph, no springs in a RemoteViews tree), so the hero play button is the only fully round control and everything else a 16dp squircle - one hero per widget. **Every control gets a container**; bare glyphs on a tonal card read as print, not buttons. Corner radii come from tinted shape drawables because `GlanceModifier.cornerRadius` is a no-op below API 31 and minSdk is 30. Colors come from `KodaWidgetTheme`, resolving the same palette/AMOLED/dynamic preferences the app does through the shared `kodaColorScheme` - Glance's default is raw system dynamic color, which makes the widgets look like another app's. The only literal color is the scrim over artwork. **A widget clips silently when content overruns the cell**, so a layout that grows is measured against the size bucket rather than eyeballed (`DeckWidget`'s `belowCoverHeight` is the pattern: add up everything under the cover and give the cover the remainder). With `SizeMode.Responsive`, `LocalSize.current` reports the matched *bucket*, not the real cell.
