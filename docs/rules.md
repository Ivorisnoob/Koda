# Invariants and settled decisions, in full

Reference detail moved out of `CLAUDE.md` so it loads only when needed. `CLAUDE.md` keeps the summary, the invariants and the silent-failure index; this file keeps the reasoning and the scars. Markers (`[verified]`, `[scar]`, `[judgement]`, `[drifts]`) mean what `CLAUDE.md` says they mean. If a change contradicts a sentence here, fix the sentence in the same commit.

## Invariants

Things that must stay true. Breaking one is a bug even when it compiles.

1. **Never hardcode a color.** Everything routes through `ColorScheme`, or palettes / AMOLED / dynamic color silently break. There are exactly **two** documented exceptions, and both are cases where the color *is* the data rather than decoration: Super Chat colors, which YouTube supplies, and SponsorBlock category colors (`SponsorCategory.color`), which are that project's own published palette and are what makes a mark on the seek bar identifiable without a legend. A theme-derived substitute would make green-means-sponsor mean something different in every palette. Everything around them - the chip, the settings rows, the track they are drawn on - still comes from `ColorScheme`; only the swatch itself is fixed.
2. **Never fetch a stream with the WEB client**, and never send a playback request with a User-Agent that does not match the URL's issuing `?c=` client (`uaForPlaybackUri()`), or googlevideo answers 403.
3. **Every googlevideo media fetch is a bounded ranged request.** Open-ended requests are paced to roughly the media bitrate. Never substitute a plain `DefaultHttpDataSource` or an unbounded OkHttp GET for a stream URL.
4. **Never route a live stream through the progressive path.** Its `adaptiveFormats` URLs are segment endpoints; the HLS manifest is the only usable source.
5. **A `MediaController` is touched only on its application thread.** Glance never gives you that thread; go through `withController`.
6. **Process-wide repository state is a closed list of ten**, each justified by "a write or expensive result taken on one surface must be visible on another holding its own instance": `LocalSubscriptionsRepository`, `NotInterestedRepository`, `SavedPlaylistsRepository`, `LocalVideoPlaylistsRepository`, `VideoHistoryRepository`, `HiddenPlaylistsRepository`, `IncognitoMode`, the `visitorData` cache, `YouTubeRateLimit`, and the short-lived video stream-resolution cache shared by watch playback, Shorts and downloads. An eleventh needs that same justification, not "it would be convenient". `HiddenPlaylistsRepository` earns it the ordinary way: a playlist hidden from the Library grid must also leave Spotlight's shelves, video mode's playlist list and the player's add-to-playlist picker, and those are three ViewModels holding three sets of repositories - a per-instance copy would leave the hidden playlist still offered as a save target, which is where a song goes missing. `IncognitoMode` earns its place the hard way: it is toggled from the account sheet and read by five write paths that each hold their own repository, and a per-instance copy would leave the player still recording history after the switch said it had stopped - for a privacy control that is a broken promise rather than a staleness bug. Transport infrastructure—the one OkHttp disk cache, dispatcher and connection pool—is not repository state; sharing it prevents duplicate locks, executors and sockets while each repository retains its own cookie jar and request interceptors.
7. **A ViewModel that needs a setting at decision time does a fresh pref read.** `ThemePreferences` StateFlow updates do not cross instances.
8. **`SettingsScreen`'s signature is the contract with `MainActivity`.** Add parameters; never reorder or restructure.
9. **Persisted enum constants are frozen.** `PlayerStyle` is stored by `name`; renaming a constant resets every existing user's choice.
10. **No emojis in code comments or docs.**

## Settled - do not re-litigate

Decisions already made, with the reasoning that made them. Re-deriving these costs a turn and usually lands somewhere worse.

- **The design language is not up for replacement.** M3 Expressive is load-bearing, not a theme layer: 65 files use Expressive-only APIs [drifts, re-derived September 2026] and the whole app renders inside one `MaterialExpressiveTheme`. A request for "a different UI", an alternate/classic/flat language, or a non-Material look is a rewrite of the entire UI and the project has a stated policy against it in `DESIGN.md`. Specific complaints - a radius, a nav-bar dimension, one animation - are normal UI work and fair game.
- **A music home is mostly artwork shelves.** [scar] Two versions of Spotlight were built and thrown away, both on the premise that horizontal shelves are what make a home feel busy, so neither had any. Every real music app is mostly shelves; without them it does not read as a music app.
- **Two Homes share one data source.** Everything Spotlight shows comes from flows `HomeViewModel` already exposes. The moment one Home owns data the other does not, there are two to keep working and one falls behind.
- **PO tokens are not the fix for stream extraction.** [verified August 2026] NewPipe ships a complete BotGuard implementation that is dead code: its `PoTokenProviderImpl` returns null for Android and iOS, and those are the only two getters `YoutubeStreamExtractor` calls - `getWebClientPoToken` has zero call sites even at the commit NewPipe itself pins. Wiring `setPoTokenProvider` on v0.26.5 is a no-op. BotGuard cannot mint an ANDROID_VR token either; that needs DroidGuard. PipePipe gets tokens only by forking the extractor. The maintained Android-reel/visionOS chain works without attestation, which is why it is the primary path.
- **Backups copy stores rather than serializing models**, so a new setting rides along for free. A `@Serializable` mirror per repository reintroduces the search-index failure: add a setting, forget the second place, discover it on restore.
- **The rate-limit hold never gates playback.** Refusing locally turns a server-side throttle into an app that looks broken.
- **Search results are never filtered by the blocklist.** Searching is explicit intent; hiding a result someone just typed the name of is the app arguing with them.
- **Explicit music playlist downloads retain an offline snapshot** (`DownloadedPlaylistStore`, owned by `DownloadRepository`). This is download intent, separate from Save: preserve ordered occurrences, join against the current downloaded-file index for playback/counts, and never treat a downloaded `LOCAL` song as a device original when retaining it. Downloads renders the snapshot without fetching the live playlist. A newly queued batch refreshes the snapshot; an already-offline tap registers a previously untracked collection. Neither is automatic synchronization.
- **Saved playlists are references, never copies.** Copying freezes someone else's playlist at the moment it was saved, which is the opposite of what saving one is for. **"Save as editable copy" does not contradict this and must not be folded into Save**: it is a separate, explicitly chosen action that takes the opposite trade knowingly - a frozen tracklist in exchange for one the user can prune, reorder and rename. Save stays the default because staying live is the right default; the copy exists because pruning a 200-track playlist down to twenty had no other route. Two buttons meaning two different things, not one button with a mode.
- **A custom app icon cannot reach the launcher, and the UI must not imply it can.** The home screen draws a static resource behind an `<activity-alias>`; there is no runtime path from arbitrary colours to one. `AppIconStyleStore` keeps a saved style, the App icon page applies the *nearest* preset alias and names it, and the style is used for Koda's own mark inside the app. A "set my colours as the launcher icon" feature is not a missing wire, it is impossible on the platform.
- **There is no master issue table.** Issue #174 was one and went stale within a day. Labels live on the issues.
